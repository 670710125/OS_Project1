# OS Simulation - Multithreaded Job Scheduler & Resource Manager

โปรแกรมจำลองการทำงานของตัวจัดคิวงาน (Scheduler) และตัวจัดการทรัพยากรร่วม (Resource Manager) ในระบบปฏิบัติการ โดยใช้ Java Multithreading เพื่อศึกษาการจัดตารางงาน การทำงานพร้อมกันของ Thread และการจัดสรรทรัพยากรที่ใช้ร่วมกัน

---

## 1. วิธี Compile และ Run โปรแกรม

### 1.1 Compile โปรแกรม

เปิด Terminal หรือ Command Prompt แล้วเข้าไปยังโฟลเดอร์ `src` จากนั้นคอมไพล์ไฟล์ Java ทั้งหมด

```bash
cd src
javac *.java
```

### 1.2 รูปแบบการรันโปรแกรม

```bash
java Main <workload_file> <policy> <num_workers> <printer_permits> <db_permits>
```

**ตัวอย่างคำสั่งรัน**

รันด้วยนโยบาย FCFS:

```bash
java Main ../workloads/jobs_standard.csv fcfs 3 1 2
```

รันด้วยนโยบาย Priority Scheduling:

```bash
java Main ../workloads/jobs_standard.csv priority 3 1 2
```

---

## 2. Command-Line Arguments

โปรแกรมรับพารามิเตอร์จาก Command Line จำนวน 5 ตัว โดยเรียงลำดับดังนี้

| ลำดับ | พารามิเตอร์ | รายละเอียด |
|---|---|---|
| 1 | `workload_file` | พาธของไฟล์ CSV ที่เก็บข้อมูลงาน เช่น `../workloads/jobs_standard.csv` |
| 2 | `policy` | นโยบายการจัดคิวงาน เลือก `fcfs` หรือ `priority` |
| 3 | `num_workers` | จำนวน Worker Threads ที่ใช้ประมวลผลงาน เช่น `3` หรือ `5` |
| 4 | `printer_permits` | จำนวน Permit สำหรับการใช้งาน PRINTER พร้อมกัน |
| 5 | `db_permits` | จำนวน Permit สำหรับการใช้งาน DATABASE พร้อมกัน |

## 3. ข้อจำกัดและเงื่อนไขของระบบ

### 3.1 ลำดับการทำงานของ Job (Strict 5-Step Lifecycle)

การประมวลผล Job ภายใน `Worker` ต้องดำเนินการตามลำดับ 5 ขั้นตอนอย่างเคร่งครัด

1. **บันทึกเวลาเริ่มงาน:** บันทึกเวลาเริ่มต้นของ Job ด้วย `jobStarted`
2. **ประมวลผลงานบน CPU:** จำลองระยะเวลาการทำงานหลักด้วย `Thread.sleep(workMs)`
3. **ขอใช้ทรัพยากร:** บันทึกเวลารอทรัพยากร และขอ Permit ผ่าน `Semaphore.acquire()`
4. **ใช้งานทรัพยากร:** จำลองระยะเวลาการถือครองทรัพยากรด้วย `Thread.sleep(resourceMs)`
5. **คืนทรัพยากรและจบงาน:** คืน Permit ด้วย `Semaphore.release()` และบันทึกเวลาสิ้นสุดงานด้วย `jobCompleted`

> **ข้อกำหนดสำคัญ:** ห้ามสลับขั้นตอนที่ 2 และ 3 เพราะจะทำให้ลำดับเหตุการณ์ในการจำลองเปลี่ยนไป และอาจส่งผลต่อการเปรียบเทียบสถิติประสิทธิภาพ

### 3.2 การจัดคิวแบบ Non-Preemptive Scheduling

ระบบใช้รูปแบบการจัดตารางงานแบบไม่แทรกกลางคัน (Non-Preemptive Scheduling)

- เมื่อ Worker รับ Job ไปประมวลผลแล้ว จะดำเนินงานนั้นต่อไปจนจบกระบวนการ
- ระบบจะไม่ยึดคืน CPU หรือสลับ Job ที่กำลังทำงานอยู่กลางคัน
- หากมี Job ใหม่ที่มี Priority สูงกว่าเข้ามาภายหลัง จะไม่มีการขัดจังหวะ Job ที่กำลังประมวลผลอยู่

### 3.3 การจัดการทรัพยากรร่วม (Resource Management)

**Single Resource Limitation**

- แต่ละ Job สามารถร้องขอทรัพยากรได้สูงสุดเพียง 1 ประเภทต่อ Job
- ทรัพยากรที่รองรับ ได้แก่ `PRINTER`, `DATABASE` และ `NONE`
- ระบบไม่รองรับการร้องขอทรัพยากรหลายประเภทพร้อมกันภายใน Job เดียว

**Fairness Guarantee**

- ระบบใช้ `Semaphore(fair = true)` เพื่อจัดลำดับการรอรับ Permit
- ช่วยลดโอกาสเกิด Thread Starvation ในระดับทรัพยากร

**Resource Safety**

- การถือครองทรัพยากรต้องจัดการด้วยบล็อก `try-finally`
- ต้องคืน Permit ด้วย `release()` ในบล็อก `finally` เมื่อได้รับ Permit แล้ว
- หากเกิด Interruption ก่อนที่จะได้รับ Permit ต้องไม่เรียก `release()` สำหรับ Permit ที่ยังไม่ได้รับ

### 3.4 การสิ้นสุดการทำงานด้วย Poison Pill Pattern

ระบบใช้เทคนิค **Poison Pill Pattern** เพื่อส่งสัญญาณให้ Worker หยุดทำงานอย่างถูกต้อง

1. `JobGenerator` และ `Scheduler` ดำเนินการสร้างและจัดคิว Job จากไฟล์ CSV จนหมด
2. ระบบส่ง Poison Pill เข้าไปใน `ReadyQueue` เพื่อแจ้งว่าไม่มีงานใหม่ให้ประมวลผลแล้ว
3. Worker แต่ละตัวจะหยุดทำงานเมื่อดึง Poison Pill จาก `ReadyQueue` ได้

จำนวน Poison Pill และลำดับการส่งต้องเหมาะสมกับจำนวน Worker เพื่อให้ Worker ทุกตัวสามารถสิ้นสุดการทำงานได้

### 3.5 รูปแบบไฟล์ Input (Workload CSV Format)

ไฟล์ CSV ต้องมีคอลัมน์ตามโครงสร้างที่ระบบกำหนด

```csv
id,arrivalMs,priority,workMs,resourceType,resourceMs
```

| คอลัมน์ | รายละเอียด |
|---|---|
| `id` | รหัสประจำ Job |
| `arrivalMs` | เวลาที่ Job เข้าสู่ระบบ หน่วยมิลลิวินาที |
| `priority` | ระดับความสำคัญของ Job |
| `workMs` | ระยะเวลาจำลองการประมวลผลบน CPU หน่วยมิลลิวินาที |
| `resourceType` | ประเภททรัพยากร ได้แก่ `PRINTER`, `DATABASE` หรือ `NONE` |
| `resourceMs` | ระยะเวลาจำลองการใช้งานทรัพยากร หน่วยมิลลิวินาที |

**ข้อควรระวัง**

- ข้อมูลแต่ละแถวต้องมีจำนวนคอลัมน์ครบถ้วน
- ค่า `resourceType` ต้องเป็นประเภทที่ระบบรองรับ
- ค่าเวลาและ Priority ต้องอยู่ในรูปแบบที่โปรแกรมสามารถอ่านได้
- ควรตรวจสอบรูปแบบ CSV ให้ตรงกับวิธีการอ่านข้อมูลในโปรแกรม

### 3.6 ความไม่แน่นอนจากการประมวลผลแบบขนาน (Non-Deterministic Nature)

เนื่องจากโปรแกรมใช้ Java Threads หลายตัวทำงานพร้อมกัน ผลลัพธ์จากการรันแต่ละครั้งอาจแตกต่างกันเล็กน้อย โดยเฉพาะ

- Timestamp ของแต่ละ Job
- ลำดับการแสดง Log จาก Worker Threads
- ค่าสถิติเวลาเฉลี่ย เช่น `avg WT`, `avg TAT` และ `avg RW`

ความแตกต่างดังกล่าวอาจเกิดจากการจัดสรรเวลา CPU ของระบบปฏิบัติการ การทำงานพร้อมกันของ Thread และความคลาดเคลื่อนของ `Thread.sleep()`

ดังนั้น แม้ใช้ Input และพารามิเตอร์ชุดเดิม ผลลัพธ์ด้านเวลาอาจไม่เหมือนกันทุกครั้ง

## 4. สรุปภาพรวมของระบบ

โปรแกรมนี้จำลองแนวคิดสำคัญของระบบปฏิบัติการ 4 ส่วน

1. **Job Scheduling:** การจัดคิวและเลือก Job ไปประมวลผลตามนโยบาย FCFS หรือ Priority
2. **Multithreading:** การใช้ Worker Threads หลายตัวเพื่อประมวลผลงานพร้อมกัน
3. **Resource Management:** การควบคุมการเข้าถึงทรัพยากรร่วมด้วย Semaphore
4. **Performance Evaluation:** การวิเคราะห์ประสิทธิภาพจากสถิติเวลาในการทำงาน การรอคิว และการรอทรัพยากร

การจำลองนี้ช่วยให้เข้าใจความสัมพันธ์ระหว่างนโยบายการจัดคิว จำนวน Worker จำนวนทรัพยากร และระยะเวลาที่ใช้ในการประมวลผล Job แต่ละรายการ
